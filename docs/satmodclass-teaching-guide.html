The project in one minute

SatModClass is a signal-analysis laboratory with a machine-learning classifier inside it. It lets someone generate or import a radio signal, inspect its properties, classify its modulation, compare results, and save reproducible reports.

You can introduce it to your juniors like this:

“Our project works with digital samples of radio signals. We use signal processing to understand their waveform and frequency content, and a trained neural network to recognize BPSK, QPSK, or 16-QAM. The application combines a React interface, a Python backend, scientific analysis, and persistent research reports.”

The easiest way to understand the project is to follow one signal from input to report.

01

Read a signal as I/Q

Start with what a signal looks like inside the computer.

A receiver supplies a sequence of I/Q samples:

x[n] = I[n] + jQ[n]

Think of each sample as an arrow on graph paper:

  • I—in-phase: its horizontal coordinate.
  • Q—quadrature: its vertical coordinate.
  • The arrow’s length represents amplitude.
  • Its angle represents phase.
  • Consecutive samples show how those properties change.

For example, a capture might look like:

Sample       I          Q
0          0.004      0.006
1          0.005      0.003
2         -0.002      0.007
...

These are two components of one complex signal. They do not automatically represent two antennas.

The sample rate supplies the clock. At 8,000 samples per second, a 128-sample window spans:

128 / 8000 = 0.016 seconds = 16 milliseconds

Also distinguish samples from symbols. A transmitter can represent one symbol using several samples. Therefore, 128 samples does not necessarily mean 128 transmitted symbols.

02

Recognize the modulation

Modulation is the pattern we are trying to recognize.

A transmitter communicates by changing a waveform’s phase, amplitude, or frequency according to symbols.

The production classifier recognizes these three schemes:

Production modulation schemes
Modulation Ideal symbol pattern Bits per symbol
BPSK Two phase states 1
QPSK Four phase states 2
16-QAM Sixteen amplitude/phase combinations 4

For an alphabet containing M symbols, each symbol can represent log2(M) bits.

A useful distinction for your juniors is:

Classification, demodulation and decoding
Task What it produces
Modulation classification A label such as “QPSK”
Demodulation Estimates of transmitted symbols
Payload decoding The recovered message after framing, coding, and other processing

SatModClass focuses on classification and analysis. Recovering satellite messages would require a fuller receiver pipeline with synchronization, symbol recovery, framing, and error correction.

TRY THE IDEA

These are mathematical symbol locations for teaching, not received measurements or CNN predictions.

04

Trace one classification

Here is exactly what happens when someone clicks “Run CNN classification.”

  1. Read the capture. Samples come from an uploaded file, a saved example, or Satellite Studio.
  2. Validate it. The backend checks channel layout, numeric values, sample count, and the selected offset.
  3. Select 128 samples. A longer recording remains available, but one complete window goes into this classification.
  4. Apply the saved normalization.
  5. Run the CNN using fixed trained weights.
  6. Return the predicted class, scores, timing, preprocessing details, and warnings.
  7. Save the analysis for later inspection and reporting.

The normalization is:

xmodel = xwindow − μtrainingσtraining

The saved mean and standard deviation come from normalization_stats_all_snr.npz.

This matters because the model learned patterns at a particular input scale. Changing preprocessing can change its predictions. The application preserves the supplied amplitude and applies the recorded transform consistently.

The contract is implemented in preprocessing.py, and classification is coordinated by classifier.py.

Clicking Classify performs inference: it uses existing weights. Training is a separate operation that changes candidate weights.

05

Look inside the CNN

The production CNN learns patterns directly from the I/Q sequence.

Its input is a 128 × 2 array. The FFT and spectrogram help people inspect the signal; the production CNN receives the normalized I/Q samples themselves.

Its actual architecture is:

Production CNN stages and output shapes
Stage Output shape
I/Q input 128 × 2
Conv1D: 32 filters, kernel 5 → ReLU → BatchNorm 128 × 32
Max pooling 64 × 32
Conv1D: 64 filters, kernel 5 → ReLU → BatchNorm 64 × 64
Max pooling 32 × 64
Conv1D: 96 filters, kernel 3 → ReLU → BatchNorm 32 × 96
Global average pooling 96
Dense layer with ReLU 64
Dense layer with softmax 3

Explain those operations in plain language:

  • Convolution: slides learned detectors across time to recognize local patterns.
  • ReLU: adds nonlinear behavior so the network can learn more complex relationships.
  • Batch normalization: applies learned feature scaling using saved statistics during inference.
  • Pooling: compresses the internal feature sequence.
  • Global average pooling: summarizes each learned feature across time.
  • Dense layers: combine those features into three class scores.
  • Softmax: converts those scores into positive values that sum to one.

The original model also has dropout layers for training. Dropout is inactive during inference.

The default application runs this network through a NumPy implementation of the saved model. NumPy carries out the convolution, normalization, pooling, and matrix calculations using the learned weights. TensorFlow is therefore optional for normal production classification.

See model_backend.py.

A high softmax score expresses a strong preference among the three classes. Its relationship to real-world correctness has not been calibrated. An unsupported external signal can still receive a confident-looking classification.

Entropy adds another view: it describes how concentrated or spread out the three scores are.

06

Read the scientific plots

Signal processing helps explain what is present in the recording.

Each plot answers a different question:

Scientific plots and their questions
View Question it helps answer
I/Q waveform How do the sample values change over time?
Constellation How are amplitude and phase distributed?
FFT/spectrum Which frequency components are present?
Power spectral density—PSD How is signal power distributed across frequency?
Spectrogram How does frequency content change over time?
Waterfall How can we inspect the time-frequency data spatially?
Phase / instantaneous frequency How does the signal rotate or change frequency?
Amplitude histogram Which magnitudes occur frequently?
Eye diagram How do known symbol intervals overlap?

Actual constellation plots can contain clouds and trajectories because of noise, filtering, timing, and channel effects. Ideal QPSK has four symbol states, but every oversampled received point need not sit exactly on one of those four locations.

The sample clock also controls units. With a known clock, frequency can be shown in Hz. With an unknown clock, normalized frequency is appropriate.

Power is generally expressed in relative sample units unless receiver calibration is supplied. An arbitrary recording alone does not uniquely reveal its noise power or true SNR.

07

Build a controlled signal

Satellite Studio supplies controlled signals for experiments.

Studio supports nine generators:

BPSK, QPSK, 8-PSK, 16-QAM, 32-QAM,
16-APSK, 32-APSK, BFSK, GMSK

The generator supports nine schemes; the production CNN supports three classes. Keep those capabilities separate when presenting.

Studio can apply:

  • Noise, controlled through SNR.
  • Doppler or carrier-frequency offset.
  • Phase noise.
  • Fading.
  • Amplifier distortion.
  • Explicit amplitude calibration.

A simplified generation chain is:

Bits → modulation and pulse shaping
     → transmitter amplitude calibration
     → amplifier distortion
     → fading
     → phase noise
     → frequency offset
     → noise
     → selected output scaling

A random seed makes experiments reproducible. You can keep the underlying generated data consistent while changing a channel parameter.

Because the simulator knows its separate clean and noise components, it can calculate a realized SNR. External recordings require independently supplied SNR information.

The simulator definitions live in signal_processing.py.

09

Make experiments repeatable

The advanced workflows make the experiments repeatable.

A binary recording needs an instruction label. SigMF supplies metadata such as sample datatype, byte order, sample rate, channel count, timestamps, and annotations.

For ambiguous inputs, the application requires explicit choices—for example, selecting a channel or specifying the zero level for unsigned samples. That prevents it from quietly applying the wrong interpretation.

Large imports and batch classifications run as background jobs with progress and cancellation. Managed window reading avoids repeatedly loading an entire large recording.

SQLite stores metadata and relationships; managed files store recordings and larger results. Saved reports retain identities such as:

  • Capture and dataset hashes.
  • Model version and artifact hash.
  • Selected window.
  • Preprocessing configuration.
  • Actual predictions and metrics.

A hash works like a fingerprint. It helps answer: “Did these two experiments actually use the same data and model?”

Signal Intelligence can compare two windows and save JSON/PDF reports. Sample-rate mismatches are explicit. Equal sample rates alone do not establish synchronized recording clocks or physical time alignment.

10

Investigate a decision

Explainability investigates the model’s decision.

The project implements two methods:

  • Saliency: measures how sensitive a selected class score is to small changes in each input sample.
  • Integrated Gradients: follows a path from a zero-raw-I/Q baseline to the actual input and accumulates contributions to the selected class score.
Read the attribution units correctly. The selected score here is the pre-softmax class logit. Saliency gives local signed derivatives per raw sample unit. The baseline-relative positive/negative contribution interpretation below applies to Integrated Gradients. Their raw magnitudes have different units.

The reports show signed I/Q contributions:

  • Positive contributions increase the selected class score relative to the baseline.
  • Negative contributions decrease it.
  • An IG completeness residual checks how closely the summed contributions match the score difference.

These describe the model’s behavior. Establishing physical causes requires additional signal experiments.

The application preserves full attribution arrays in machine-readable exports and renders plots in technical PDFs.

11

Train and compare candidates

Training and evaluation are separate research workflows.

The supplied production model is already trained. Its complete original training data and split history were not supplied.

The offline pipeline lets researchers train new candidates with controlled provenance:

Training, validation and test responsibilities
Split Purpose
Training Fit model parameters and training normalization
Validation Select settings, checkpoints, and supported calibration
Test Measure the frozen candidate on held-out data

A crucial rule is session separation. Adjacent windows from the same recording can be very similar. Putting related windows into both training and testing can make evaluation look better than genuine generalization.

The registry-to-training bridge checks splits, duplicates, sessions, and known held-out provenance before exporting NPZ data and experiment configuration. Missing SNR remains explicitly unavailable.

The project includes these model approaches:

The production and experimental model approaches
Model Approach
Production CNN Learns local patterns from I/Q sequences
Experimental Random Forest Uses engineered statistical features and decision trees
Experimental ResNet Uses convolution blocks with skip connections
Experimental CLDNN Combines convolutional features with an LSTM for temporal relationships

Here, RF model means Random Forest; RF recording means radio-frequency recording. Spell those out when teaching to avoid confusion.

Experimental models use their own recorded preprocessing and runtime requirements. Their availability is shown honestly in the application.

12

Put accuracy in context

When someone asks “How accurate is it?”, explain the evidence before the percentage.

The historical report contains 900 observations, with 652 correct predictions:

652 ÷ 900 ≈ 72.44%

That describes that stored evaluation. Independent performance on a new receiver, channel, or satellite dataset requires fresh labeled evaluation.

The supplied 300-frame demo library is a separate subset with unknown split provenance. It cannot recreate the complete historical evaluation and is excluded from fitting.

The project also contains genuine synthetic experiments. Comparisons are meaningful when models use the same held-out windows and protocol. Arena enforces those identities.

Explain the main metrics this way:

  • Accuracy: how many predictions were correct overall?
  • Precision: when the model predicts a class, how often is it correct?
  • Recall: how many actual examples of that class did it find?
  • F1: how well does it balance precision and recall?
  • Confusion matrix: which classes are being confused?

Automated tests verify parsing, calculations, model behavior, APIs, persistence, and browser workflows. Independent RF evaluation establishes how well the classifier generalizes to real acquisitions.

14

Teach the team

For your junior demonstration, use this sequence:

  1. Draw an I/Q arrow and the three ideal modulation patterns.
  2. Generate a seeded QPSK signal in Studio.
  3. Inspect its waveform, constellation, and spectrogram.
  4. Classify a complete 128-sample window.
  5. Reduce SNR and observe the changes without promising a particular prediction.
  6. Inspect a class explanation and export its report.
  7. Open history to show persistence.
  8. Finish in Arena by explaining why fair comparisons require identical test data.

Then ask them three questions: What does one I/Q sample represent? What happens between clicking Classify and receiving a label? What evidence would justify trusting the model on a new recording?

CHECK UNDERSTANDING

Let the juniors explain it back.

Try an answer before opening each explanation.

01What does a single I/Q sample represent?

One complex-signal observation: I is the horizontal component and Q the vertical component. Together they describe amplitude and phase at a sampling instant.

02The simulator has nine schemes. How many classes does the production CNN recognize?

Three: BPSK, QPSK and 16-QAM. Generator capability and classifier coverage are separate.

03What does receiving a QPSK classification tell us about the payload?

It identifies the predicted modulation family. Recovering the message additionally requires receiver synchronization, symbol recovery, framing and error correction.

04How long is a 128-sample window at 8,000 samples per second?

128 / 8,000 = 0.016 seconds, or 16 milliseconds. A physical duration requires a known sample clock.

05Does a high softmax score establish real-world correctness?

It expresses preference among the three learned classes. It is uncalibrated and can be high for an unsupported external signal.

06Why keep related recording windows in the same data split?

Neighboring windows can be very similar. Splitting related data across training and test can leak information and exaggerate generalization performance.
